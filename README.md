# Telegram-бот «Мойдодыр»

Бот на aiogram 3 принимает заявки, показывает предварительный расчёт, передаёт заявки менеджерам в Telegram и сохраняет данные в PostgreSQL.

## Структура проекта

- `moydodyr/app.py` — создание бота, подключение роутеров и запуск фоновой очереди.
- `moydodyr/bot/handlers/` — обработчики по сценариям: меню, админ-команды, заказ, связь с менеджером, фото и группа.
- `moydodyr/bot/keyboards.py`, `states.py`, `formatting.py` — клавиатуры, состояния диалога и форматирование карточек.
- `moydodyr/bot/services/` — доставка очереди уведомлений и обработка фотоальбомов.
- `moydodyr/integrations/` — внешние интеграции, включая n8n.
- `moydodyr/db.py`, `domain.py`, `config.py` — база данных, правила предметной области и конфигурация.

## Запуск

Требуются Python 3.12+, Docker Desktop и токен Telegram-бота от BotFather.

1. Скопируйте `.env.example` в `.env`, задайте `POSTGRES_PASSWORD` и укажите такой же пароль в `DATABASE_URL`.
2. Запустите PostgreSQL: `docker compose up -d`.
3. Укажите `BOT_TOKEN`, `MANAGER_CHAT_ID` и `ADMIN_IDS` в `.env`.
4. Установите зависимости: `uv sync`.
5. Запустите: `uv run python main.py`.

Контейнер публикует PostgreSQL только на `127.0.0.1:5432` и хранит данные в Docker volume. При первом подключении бот создаёт таблицы и загружает `catalog.json`, если запись каталога ещё отсутствует. Последующие настройки хранятся в PostgreSQL.

В личном чате бот показывает одно приветственное сообщение с кнопкой «✨ Открыть приложение». Любое сообщение клиента повторно показывает это приветствие; старые кнопки отвечают предложением открыть `/start`. При отсутствии `MINI_APP_URL` бот сообщает, что приложение пока недоступно. После отправки заявки клиент также получает подтверждение через outbox, а менеджеры — уведомления.

Прежние клиентские обработчики, экраны и каталог сохранены в коде, но их роутеры не подключаются в текущей версии. Команды администратора в личном чате и прежний клиентский кабинет поэтому также недоступны. Уведомления группы и ответы старых кнопок управления в группе остаются активными.

Состояние экрана хранится в PostgreSQL вместе с FSM, а кнопки завершённых шагов отклоняются.

Подтверждение принятой заявки доставляется через outbox редактированием того же экрана. Если пользователь уже перешёл к другому экрану или новому сценарию, квитанция приходит отдельным уведомлением и не заменяет текущий шаг. Уведомления менеджерам продолжают поступать отдельно.

Кнопка «Назад» возвращает на предыдущий шаг оформления в том же сообщении. История шагов хранится в FSM; при возврате восстанавливаются состояние, кнопки и черновик того шага. Изменённый выбор требует заново пройти последующие шаги, чтобы прежние данные и расчёт не попали в заявку. Ошибки ввода, переключение страниц и выбор нескольких дополнительных услуг не добавляют лишних шагов в историю. Выход в главное меню очищает историю сценария.

Сообщение клиента с площадью удаляется после обновления экрана: при корректном вводе площадь сохраняется в FSM, при ошибке появляется предупреждение с ❗ и просьбой ввести корректное значение. Отказ Telegram удалить сообщение не прерывает оформление.

Сообщение с корректным адресом или геолокацией также удаляется после сохранения адреса и перехода к календарю. Адрес остаётся в черновике и отображается при проверке заявки.

Сообщения с корректным именем и телефоном (включая отправленный контакт) удаляются после сохранения значения и обновления экрана следующего шага. Имя и телефон остаются в черновике и карточке подтверждения заявки.

Принятый комментарий также удаляется после перехода к фотографиям и остаётся в черновике заявки. Нажатие inline-кнопки «Пропустить» не удаляет основное сообщение бота.

Сохранённые фотографии удаляются из клиентского чата после записи самих файлов в PostgreSQL и обновления счётчика; их Telegram `file_id` также остаются в FSM и заявке для передачи менеджеру. Это работает и для альбомов. Фото сверх лимита пяти не удаляются, поскольку в заявку они не сохранены. При ошибке скачивания или записи файл остаётся в чате, бот предлагает отправить его повторно.

При входе в «Рассчитать стоимость» картинка в текущем сообщении меняется на `assets/estimate.png` и сохраняется на шагах расчёта. Возврат в главное меню восстанавливает `assets/welcome.png`; новое сообщение для смены картинки не создаётся.



Раздел «Услуги и цены» использует `assets/services.png`: показывает тарифы «от» за м² для квартиры и дома, минимальную стоимость уборки и цены дополнительных работ. Значения берутся из действующего каталога в PostgreSQL; выключенные услуги скрываются, для незаданных тарифов предлагается уточнить цену у менеджера.

Оформление заявки использует `assets/order.png`, в том числе при переходе к заявке после расчёта. «Назад» из оформления к результату расчёта восстанавливает картинку расчёта, а главное меню — приветственную.

## Telegram Mini App

Mini App позволяет выбрать услуги, получить предварительный расчёт и отправить заявку с фотографиями; прежний диалоговый сценарий сохранён в коде и временно отключён. Перед отправкой клиент проверяет данные заявки. Расчёт, валидация и идентификация по подписанному `initData` выполняются на сервере; заявки и уведомления сохраняются через обычный `Database.submit()`.

1. Установите зависимости `uv sync --locked` и запустите PostgreSQL и бота по инструкции выше.
2. Запустите веб-сервер отдельно: `uv run python -m moydodyr.miniapp.server`. По умолчанию он слушает `127.0.0.1:8080`; адрес и порт задаются через `MINI_APP_HOST` и `MINI_APP_PORT`.
3. Настройте публичный HTTPS-адрес с обратным прокси на этот сервер. Прокси должен передавать корневой путь `/`, `/static/` и `/api/`, принимать загрузки до 20 МиБ и не записывать заголовок `X-Telegram-Init-Data` в логи. Telegram не может открыть адрес localhost на компьютере пользователя.
4. Укажите полный HTTPS-адрес корня в `MINI_APP_URL` в `.env` и перезапустите бота. В главном меню появится кнопка «✨ Открыть приложение». Приложение нужно открывать из личного чата с ботом: без проверенных данных Telegram API не работает.

Фотографии из Mini App сохраняются в `photo_files` до отправки заявки, связываются с ней в той же транзакции и доставляются менеджеру из outbox. У таких фотографий нет Telegram `file_id`: в webhook поле `file_id` равно `null`, а CRM получает файл по `photo_id` с проверкой владельца. Поддерживаются JPEG, PNG и WebP, до пяти файлов по 20 МиБ. Незавершённые загрузки остаются в базе как фотографии черновика.

## Фотографии для CRM

- `photo_files` хранит бинарные данные в `content` (`bytea`), постоянный UUID файла, Telegram ID клиента и черновика, `telegram_file_id`, `telegram_unique_id`, MIME-тип, размер, SHA-256 и размеры изображения, если они известны. Скачивается наибольший размер фотографии из Telegram, проверяются формат, полный размер загрузки и ограничение 20 МиБ.
- `order_photos` связывает файл с заявкой и его позицией. Связи создаются в одной транзакции с заявкой и outbox; файлы сохраняются уже при загрузке в черновик. Повторная обработка одной фотографии того же клиента и черновика использует существующий файл.
- `Database.customer_order_photos(user_id, order_id)` возвращает метаданные вложений. `Database.customer_order_photo(user_id, order_id, photo_id)` возвращает файл, включая `content`, после проверки владельца на уровне SQL. CRM может использовать эти методы в своём авторизованном серверном обработчике.
- В новых webhook n8n поле `photos` содержит `photo_id`, позицию, Telegram `file_id`, MIME-тип, размер, SHA-256 и размеры изображения; `telegram_user_id` содержит владельца заявки. Файлы извлекаются по ID из БД. Бинарные данные и URL Telegram с токеном в webhook не передаются.
- При запуске схема восстанавливает ссылки на фотографии старых заявок из `orders.payload.photos`, а фоновая задача архивирует доступные файлы из Telegram. Неудачные загрузки остаются для следующей попытки при запуске; исходные Telegram ID сохраняются. Уже отправленные webhook повторно не отправляются. Файлы незавершённых черновиков сохраняются в `photo_files` без связи с заявкой.

## Личный кабинет клиента

Клиент регистрируется автоматически по Telegram ID при `/start`, входе в «Мои заявки» или сохранении первой заявки. Повторные входы используют ту же запись и сохраняют первоначальный источник перехода. Имя пользователя `@username` не используется для проверки владельца.

Кнопка «📋 Мои заявки» и команда `/orders` открывают кабинет в том же сообщении:

- «Актуальные» — новые заявки, заявки в работе и согласованные на сегодня или будущие даты.
- «История» — отменённые заявки и согласованные на прошедшие даты. Выполненные заявки также попадают в историю.
- Список показывает пять заявок за раз; в карточке доступны параметры уборки, предварительная цена и последние 20 изменений статуса.

Каждый запрос списка, карточки, истории и отмены ограничен Telegram ID текущего клиента на уровне SQL. Ранее оформленные заявки доступны сразу, переносить данные не требуется.

Клиентский кабинет доступен только для чтения. Для переноса или отмены клиент связывается с менеджером; изменения выполняются в CRM. Старые кнопки отмены не меняют данные и предлагают обратиться к менеджеру.

## Управление через CRM

Взятие заявки, редактирование, назначение менеджера и бригады, согласование времени, перенос, отмена и завершение выполняются в соседнем проекте `мойдодырадмин`. Telegram-кнопки управления удалены; старые callback-кнопки отвечают сообщением о переносе в CRM. Новые уведомления менеджерам приходят без управляющих кнопок. Команды каталога `/admin` сохранены.

Общая схема добавляет статус `completed`, поле `orders.crm` и таблицу `crm_events`. `crm` хранит подтверждённый выезд, бригаду, менеджера, заметку, согласованную цену и исходное пожелание клиента. CRM синхронизирует подтверждённые дату/время с payload заявки, поэтому клиентский кабинет показывает актуальный выезд. Выполненные и отменённые заявки находятся в истории.

По выбору оператора CRM ставит клиентское уведомление в outbox атомарно с изменением заявки и аудитом. Бот доставляет его как текст без внутренних заметок и состава команды. При обновлении требуется перезапуск единственного polling-процесса.

## Проверки

`uv run pytest` запускает проверки с подменённым Telegram API без реальных сообщений и заявок. Интеграционные проверки PostgreSQL включаются переменной `RUN_DB_TESTS=1`: `uv run pytest tests/test_customer_db.py tests/test_photo_db.py`. Они используют подключение из `.env` только для создания отдельных временных баз `test_moydodyr_<uuid>`, проверяют схему, разграничение доступа, отмену, бинарные вложения и откат транзакций и удаляют только созданные тестовые базы. Нужны работающий PostgreSQL и право `CREATE DATABASE`.

## Передача заявок в n8n

После подтверждения заказа бот ставит в очередь POST-запрос на URL из `N8N_WEBHOOK_URL`. Тело содержит `name`, `phone`, `telegram`, `service`, `address`, `date`, `price`, `comment`, а также дополнительные поля. Секрет добавляется в поле `secret` только при отправке и не сохраняется в очереди.

Успешный ответ HTTP 200 с `ok: true` отмечает доставку; возвращённый `lead_id` сохраняется в заявке. Сетевые и серверные ошибки повторяются через очередь; неверный секрет (HTTP 401) помечает доставку как неуспешную без повторов. Значения URL и секрета задаются в `.env`, в Git они не коммитятся.

Добавьте бота в рабочую группу менеджеров и выдайте ему право отправлять сообщения. Значение `MANAGER_CHAT_ID` — числовой ID этой группы. В `ADMIN_IDS` укажите Telegram ID менеджеров, которым разрешено менять настройки каталога.

В разделе «Связаться с менеджером» кнопка «Написать администратору» открывает личный чат `@Moydodyr_msk` по ссылке `https://t.me/Moydodyr_msk`. Сообщения через бота не пересылаются: общение проходит напрямую в личном чате администратора. Эта контактная ссылка не меняет права доступа из `ADMIN_IDS`.

## Команды администратора

Отправьте `/admin`, чтобы увидеть формат команд. Например:

- `/admin price regular flat 120` — цена услуги за квадратный метр;
- `/admin minimum regular 5000` — минимальная стоимость;
- `/admin extra windows 350` — цена дополнительной услуги;
- `/admin enabled service renovation false` — выключить услугу;
- `/admin text promotions Новая акция` — изменить текст акции.

Ключи услуг и дополнительных работ указаны в `catalog.json`. Команда `/start` показывает клиентское меню, `/menu` — возвращает его из диалога.

## Ограничения текущей версии

- Даты и время — пожелания клиента; бот не проверяет график бригад.
- Расчёт появляется только при заполненных тарифе за м² и минимальной цене выбранной услуги. Дополнительная работа требует заданной цены.
- Фотографии отправляются отдельными сообщениями после карточки заявки.
- Менеджер связывается с клиентом напрямую; ответы через бот не маршрутизируются.
- Для доставки уведомлений используется PostgreSQL outbox с повторными попытками.

# Развёртывание Mini App

На сервере используется каталог `/opt/moydodyr`, отдельный Compose-проект `moydodyr` и контейнеры `database`, `bot`, `miniapp`, `https`. Compose запускается из каталога приложения с `--project-directory .`:

```sh
cd /opt/moydodyr
docker compose -f deploy/compose.yaml --project-directory . ps
docker compose -f deploy/compose.yaml --project-directory . logs --tail 100 bot miniapp https
```

Контейнеры используют host network без изменения правил Docker для опубликованных портов. PostgreSQL слушает только `127.0.0.1:15432`, Mini App — `127.0.0.1:18081`; Caddy привязан к адресу из `CADDY_BIND`, не ко всем адресам сервера, и управляет HTTPS для `CADDY_SITE`. Его данные сертификатов и база хранятся в отдельных Docker volumes. Секреты находятся в `/opt/moydodyr/.env` с правами 600, в Git их не копируют.

Зависимости собираются из `deploy/requirements.txt`, экспортированного из `uv.lock` командой `uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file deploy/requirements.txt`. При обновлении lock-файла обновляйте и этот экспорт. Для нового развёртывания `.env` должен содержать настройки бота, `POSTGRES_PASSWORD`, `DATABASE_URL` с портом 15432, `MINI_APP_HOST=127.0.0.1`, `MINI_APP_PORT=18081`, `MINI_APP_URL`, `CADDY_BIND` и `CADDY_SITE`.

Серверная версия переключена с локальной 11.11.2026. Перед переключением бот на компьютере остановлен, база перенесена в новую базу сервера. Исходная база на компьютере оставлена; копия до миграции хранится на сервере в `/root/backups/moydodyr/local-before-migration.dump` (только root). После переключения локальная база не синхронизируется с серверной. При откате сначала остановите серверный polling, перенесите актуальную серверную базу и только затем запустите локальный бот: один токен допускает один polling-экземпляр.

Проверки 11.11.2026: PostgreSQL healthy; публичный HTTPS `/` — 200, неподписанный `/api/catalog` — 401, запросы каталога и расчёта с проверяемой тестовой подписью — 200; в журнале бота подтверждён polling. Реальная заявка и доставка фотографий в Telegram при развёртывании не создавались. Рабочая служба VPN оставалась активной, её конфигурация и службы не перезапускались. Доступность и получение сертификата зависят от публичного DNS-имени и портов 80/443; для постоянного использования рекомендуется собственный домен.
